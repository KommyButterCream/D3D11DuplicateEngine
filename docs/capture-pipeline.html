Module / D3D11DuplicateEngine

초기화부터 프레임 발행까지, 그리고 실패했을 때

DXGI Desktop Duplication 기반 화면 캡처 엔진의 전체 흐름과 예외 처리를 한 곳에 정리했습니다. 각 실패 지점이 어떤 이벤트를 쏘고 어떤 카운터를 올리는지, 그때 호출자가 무엇을 해야 하는지까지 포함합니다.

출력 모드 FramePool · SharedTexture 스레드 캡처 · 소비자 · 호출자 풀 크기 4 슬롯 기준 현재 작업 트리

구조 한눈에

엔진은 스레드 하나(캡처 스레드)를 돌리고, 결과를 두 가지 방식 중 하나로 내보냅니다. 어느 쪽을 쓰느냐에 따라 동기화 주체와 실패 양상이 완전히 달라집니다.

FramePool

텍스처 4장을 돌려 쓰는 대여 방식

소비자가 GetLatestFrameHandle로 빌려 가고 ReleaseLatestFrameHandle로 반납합니다. 풀 텍스처는 MiscFlags = 0이라 공유가 불가능하므로, 소비자는 구조적으로 같은 디바이스·같은 immediate context입니다. 엔코더 연결이 이 경로입니다.

SharedTexture

공유 핸들 1장을 keyed mutex로 교대

GetSharedTextureHandle로 받은 핸들을 다른 디바이스에서 OpenSharedResource로 엽니다. 캡처가 키 0, 뷰어가 키 1을 잡는 엄격한 교대라 뷰어가 놓아줘야 다음 프레임이 만들어집니다. 로컬 뷰어 연결이 이 경로입니다.

01초기화 순서

설정 중 일부는 Initialize 이후 바뀌지 않습니다. 순서를 어기면 조용히 무시되는 게 아니라 false를 반환하므로 반환값을 봐야 합니다.

  1. 초기화 전용 설정

    SetCaptureOutputMode · SetImmediateContextGateEnabled · SetWaitForFrameCopyCompletion. 셋 다 IsInitialized()가 참이면 false를 반환하고 아무것도 바꾸지 않습니다.

  2. Initialize(engine, outputIndex)

    엔진을 넘기면 그것을 쓰고(소유하지 않음), nullptr이면 내부에서 D3D11RenderEngine을 만들어 소유합니다. 외부 엔진에 게이트 설정이 어긋나면 즉시 실패합니다.

  3. InitializeDuplication

    EnumAdapters1(0) → EnumOutputs(index) → QueryInterface(IDXGIOutput1) → DuplicateOutput → GetDesc. 실패하면 자기가 잡은 COM 객체를 전부 놓고 나갑니다 — 재연결이 같은 함수를 반복 호출하기 때문입니다.

  4. CreateFrameResources

    m_duplDesc.ModeDesc 크기로 출력 리소스를 만듭니다. FramePool이면 텍스처 4장(+선택적 쿼리), SharedTexture면 공유 텍스처 1장과 keyed mutex. 재연결 후 해상도가 바뀌었을 때도 같은 함수를 탑니다.

  5. 콜백 · 런타임 설정

    SetFrameCaptureCallback · SetCaptureEventCallback · SetTargetFps · SetSkipUnchangedFrames. 전부 언제든 바꿀 수 있고, 콜백은 userData를 먼저 심은 뒤 함수 포인터를 공개합니다.

  6. StartThread

    IsInitialized()가 참일 때만 시작합니다. 스레드는 fps == 0이면 무제한, 아니면 주기 waitable timer로 페이싱합니다.

상태 전이

Initialize가 성공한 시점에 상태가 Idle → Running으로 바뀝니다. Shutdown은 스레드를 멈추고 duplication을 놓은 뒤 Idle로 되돌립니다.

02캡처 상태 기계

캡처 스레드는 매 반복마다 상태를 먼저 확인합니다. 상태가 곧 그 반복에서 무엇을 할지를 결정합니다.

03프레임 파이프라인

Running 상태의 한 반복입니다. 중간에 빠져나가는 길이 다섯 갈래 있고, 각각 올리는 카운터가 다릅니다.

숫자를 비교할 때 주의

AcquireNextFrame은 present를 합쳐서 돌려줍니다. 루프가 느리면 한 프레임이 여러 present를 대표하므로, 설정을 바꿔가며 capturedFrames 절대값을 비교하는 것은 등가 비교가 아닙니다. 보장되는 것은 “스킵된 프레임은 계약상 화면 변화가 없다”이지 “프레임 수가 같다”가 아닙니다.

04슬롯 소유권 규약

FramePool 경로에서 생산자와 소비자가 락 없이 슬롯을 주고받는 방식입니다. 참조 카운트와 상태를 양쪽 모두 두 번씩 확인하는 것이 핵심입니다.

핸들 반납 규약

반납에 필요한 것은 texture · slotId · frameId 셋뿐입니다. 이 셋만 따로 보관했다가 나중에 구조체를 재조립해 반납해도 됩니다 — 큐를 거치는 소비자가 실제로 그렇게 씁니다.

그래서 CapturedFrameHandle에 “반납에 필요한 네 번째 필드”를 추가하면 안 됩니다. 재조립하는 쪽이 그 필드를 채우지 못해 참조 카운트가 영영 줄지 않고, 슬롯 4개가 모두 물린 뒤 모든 프레임이 드롭됩니다.

05공유 텍스처 핑퐁

SharedTexture 모드는 디바이스 경계를 넘기 때문에 참조 카운트를 쓸 수 없고, keyed mutex의 키 교대로 소유권을 넘깁니다.

뷰어가 없으면 멈춥니다

캡처는 키 0으로 얻어 키 1로 놓습니다. 아무도 키 1을 받아 키 0으로 돌려주지 않으면 첫 프레임 이후 모든 프레임이 드롭됩니다. 뷰어가 붙어 있어도 렌더 스레드 속도가 곧 캡처 속도의 상한이 됩니다. 소비자가 항상 붙어 있지 않는 구성이라면 FramePool을 쓰십시오.

각 실패 지점이 무엇을 하고, 무엇을 통지하고, 어떤 카운터를 올리는지 그리고 호출자가 무엇을 해야 하는지. 정상은 대응이 필요 없는 정상 동작, 손실은 프레임 유실, 중단은 캡처가 멈추는 상황입니다.

08처리하지 않는 것

아래는 현재 구현이 다루지 않는 영역입니다. 알고 쓰는 것과 모르고 밟는 것의 차이가 커서 함께 적어 둡니다.

미지원

HDR 데스크톱

출력이 R16G16B16A16_FLOAT로 나오면 포맷이 맞지 않아 복사가 조용히 실패합니다. 현재 감지도 거절도 하지 않으므로 검은 화면으로 나타납니다. 캡처 대상 출력의 HDR을 꺼야 합니다.

미지원

회전된 디스플레이

m_duplDesc.Rotation을 사용하지 않습니다. 90·270도로 돌려 쓰는 모니터에서는 폭과 높이가 뒤바뀐 채로 나옵니다.

미지원

Windows 서비스(Session 0)

Desktop Duplication은 대화형 세션이 필요합니다. 서비스로 배포하려면 세션에 붙는 에이전트 프로세스가 따로 있어야 하고, 잠금화면 전환을 따라가려면 데스크톱 전환 처리도 필요합니다.

제약

어댑터 0 고정

출력을 항상 첫 번째 어댑터에서 찾습니다. DuplicateOutput은 디바이스와 출력이 같은 어댑터여야 하므로, 멀티 GPU 구성에서 두 번째 GPU에 붙은 모니터는 잡지 못합니다.

미노출

마우스 커서 · dirty rect

수집 코드는 있지만 켤 수 있는 설정이 없어 실행되지 않습니다. duplication 이미지에는 커서가 그려져 있지 않으므로, 지금 캡처 결과에는 마우스가 보이지 않습니다.

미노출

프레젠테이션 타임스탬프

슬롯은 LastPresentTime을 갖고 있지만 핸들로 꺼낼 수 없습니다. 인코더 PTS를 자체 시계로 찍고 있다면 A/V 동기와 지터 보정이 부정확해집니다.

현재 작업 트리 기준. 회전·HDR 처리는 의도적으로 범위에서 제외되어 있습니다.
